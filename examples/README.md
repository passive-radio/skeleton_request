# skeleton_request Examples

## Cat API Test Example

The `test_cat_api.py` script demonstrates real-world tracing with The Cat API.

### Setup

1. Install dev dependencies:
```bash
uv sync --extra dev
```

2. Ensure `.env.local` exists in project root with:
```
CAT_API_KEY=your-api-key-here
```

### Running Tests

```bash
# Test Method 1: Function replacement pattern
uv run python examples/test_cat_api.py --method1

# Test Method 2: Decorator pattern on specific functions
uv run python examples/test_cat_api.py --method2

# Test both methods
uv run python examples/test_cat_api.py --both
```

### What Gets Traced

The script tests 3 Cat API endpoints:
- `GET /v1/images/search?limit=5` - Random cat images
- `GET /v1/images/{id}` - Specific image details
- `GET /v1/breeds` - Cat breeds list

### Two Implementation Patterns

**Method 1: Function Replacement**
```python
@trace
def my_request(method, url, **kwargs):
    return requests.request(method, url, **kwargs)

# Use my_request instead of requests.request
response = my_request("GET", url, headers=headers)
```

**Method 2: Decorator on Functions**
```python
@trace
def fetch_cat_images(limit=5):
    return requests.get(url, headers=headers, params={"limit": limit})

# Call the decorated function directly
response = fetch_cat_images()
```

## Basic Usage

### 1. Trace Mode (Record API Calls)

```bash
# Set environment variables
export SKELETON_MODE=trace
export SKELETON_TRACE_DIR=./traces

# Run your application with traced requests
python basic_usage.py trace
```

This will create `.ndjson` files in `./traces/` containing API request/response schemas.

### 2. Build Emulation Environment

After collecting traces, build the emulation environment:

```bash
# Basic build (schemas only)
skeleton build-env --trace-dir ./traces --output-dir ./skel_env

# With type inference (requires OPENAI_API_KEY)
export OPENAI_API_KEY=your-key-here
skeleton build-env \
  --trace-dir ./traces \
  --output-dir ./skel_env \
  --infer-types

# Privacy-preserving mode (key names only, no values)
skeleton build-env \
  --trace-dir ./traces \
  --output-dir ./skel_env \
  --infer-types \
  --key-names-only
```

### 3. Generate Documentation

```bash
skeleton gen-docs --spec-dir ./skel_env --output-dir ./docs
```

### 4. Emulate Mode (Replay Responses)

```bash
# Set environment variables
export SKELETON_MODE=emulate
export SKELETON_ENV_DIR=./skel_env

# Run your application with emulated responses (no network required!)
python basic_usage.py emulate
```

## Advanced Usage

### Environment Variables

- `SKELETON_MODE`: `trace` | `emulate` | `off`
- `SKELETON_TRACE_DIR`: Directory for trace files (default: `./traces`)
- `SKELETON_ENV_DIR`: Directory with .skel.json files (default: `./skel_env`)
- `OPENAI_API_KEY`: OpenAI API key for type inference
- `OPENAI_BASE_URL`: Custom base URL for OpenAI-compatible APIs
- `SKELETON_LLM_PROVIDER`: `openai` | `azure` | `gemini`
- `SKELETON_LLM_MODEL`: Model name (default: `gpt-4o-mini`)

### Using with Azure OpenAI

```bash
export SKELETON_LLM_PROVIDER=azure
export OPENAI_API_KEY=your-azure-key
export OPENAI_BASE_URL=https://your-resource.openai.azure.com/
export SKELETON_LLM_MODEL=gpt-4

skeleton build-env --infer-types
```

### Simulate Realistic Values with LLM

```python
from skeleton_request import emulate, EmulationEnv, LLMProvider

env = EmulationEnv.load_from_dir("./skel_env")
llm_provider = LLMProvider()

@emulate(env, simulate_value=True, llm_provider=llm_provider)
def request(method, url, **kwargs):
    return requests.request(method, url, **kwargs)

# Response will have realistic values generated by LLM
response = request("GET", "https://api.example.com/users/1")
```
